# Product Requirements Document (PRD): `next.xz`

**Version:** 0.1.0-draft
**Status:** Proposal
**Author:** Xz Core Team & AI Architecture Working Group
**Target architecture:** Next.js (TypeScript) + Xz native compiler/JIT
(`xz check-json`, `xz build --shared`)

---

## 1. Executive summary

### 1.1 Vision and thesis

`next.xz` is a hybrid web framework and orchestration toolkit that bridges
**Next.js (TypeScript)** with the **Xz programming language**. It is built
around a single thesis:

> **AI-written, Human-reviewed.**

Next.js stays the industry-standard UI and routing shell. `next.xz` delegates
core business logic and backend computation to Xz. Xz's strong static typing,
value semantics, and explicit contract mechanisms (`@intent`, `@requires`,
`@ensures`, `@effects`, `@trusted`) let AI Agents:

- generate backend code with no silent mutations and no unhandled failure
  paths,
- self-correct from structured compiler feedback (`xz check-json`),
- expose verifiable side effects so a human can audit the result in seconds.

### 1.2 Scope

In scope: the TypeScript-side bridge, the agent self-correction pipeline, and
the human audit interface.

Out of scope: the Xz language, compiler, and runtime themselves. Those live in
the [Xz repository](https://github.com/x1zzdev/Xz). `next.xz` consumes their
stable surfaces — the CLI, JSON diagnostics, shared-library ABI, and `.xzint`
interface files.

## 2. Problem statement and opportunities

| Problem | Opportunity |
|---|---|
| **Ambiguity in TS/JS for AI Agents.** TypeScript's dynamic escape hatches and runtime meta-programming let LLMs produce code with hidden side effects and runtime bugs. | **Strict Xz boundaries.** Xz forces explicit contracts. The compiler derives the real effect profile from the body and rejects a mismatch with the declared `@effects` (`I0020`). Silent mutation and undeclared I/O are compile errors. |
| **High audit overhead.** Humans spend too long reading multi-file TS PRs generated by AI, hunting for subtle logic and security bugs. | **One-glance verification.** Reviewers read structured contract and effect badges plus a diff, not whole code paths. |
| **Feedback-loop friction.** Standard compiler output is written for human eyes, which is poor input for LLM self-correction. | **Native JSON diagnostics.** `xz check-json` emits stable codes, machine-readable spans, categories, and suggested fixes for the repair loop. |

## 4. Personas and core workflow

### 4.1 Personas

1. **The Product Architect (Human).** Writes product requirements and Next.js
   UI, defines the intent of each backend unit, and reviews/approves generated
   Xz contracts.
2. **The AI Agent (Writer).** Receives an intent specification, writes the `.xz`
   implementation, reads `xz check-json` output, and repairs compiler errors
   independently within a bounded retry budget.

### 4.2 Core workflow

1. **Define intent.** Human or agent creates a `.xz` contract shell with
   `@intent` and `@effects`.
2. **AI generation.** The agent completes the implementation.
3. **Deterministic verification.** `next.xz` runs `xz check-json`. Type,
   contract, and effect violations are fed back to the LLM for self-correction
   (up to N retries).
4. **Human audit.** On zero errors, `next.xz` renders an Audit Card:
   - `@intent` claim vs. implemented logic summary,
   - declared vs. derived `@effects` (e.g. `io`, `extern`, `mut`),
   - code diff.
5. **Compilation and binding.** On approval, `next.xz` compiles via
   `xz build --shared` and generates TypeScript bindings.

## 5. Key feature requirements

### 5.1 FFI and interoperability bridge (`@xz-lang/bridge`)

- **P0** — Automated TypeScript wrapper generator over `.xzint` interface
  files, implemented in `@xz-lang/bridge`. It consumes the same interface the
  existing `xz pkg gen --lang python` flow uses but does not become a CLI
  `--lang ts` target: the generated module depends on the bridge runtime (see
  [docs/01-bridge.md](docs/01-bridge.md) §2.2).
- **P0** — Direct call path for Next.js Server Actions into compiled Xz shared
  libraries (`.so` / `.dylib` / `.dll`), using `bun:ffi` on Bun and a
  Node-compatible FFI (e.g. `koffi` / an N-API addon) on Node.
- **P0** — Only `@export` functions cross the boundary. Every exported
  signature must be C-representable end to end (`Bool`, `Int`, `usize`,
  `Float`, `Char`, `Str`, `Bytes`, `Ptr`, `@cstruct record`; `Unit` return
  only). The bridge surfaces a clear error when a signature is not
  C-representable rather than silently degrading it.
- **P0** — An `.xzint` declares its interface kind explicitly with a mandatory
  `@interface export` or `@interface foreign` marker; ownership rules
  (`transfer`, `release`) key off it rather than a per-file assumption. See
  [docs/01-bridge.md](docs/01-bridge.md) §2.1.
- **P1** — Zero-copy transfers between V8 `ArrayBuffer`/`TypedArray` and Xz
  `Str`/`Bytes`/`@cstruct` values.
- **P1** — `Result`/`Option` marshalling. A C ABI export cannot carry a
  `Result`; the sanctioned pattern is a thin contracted Xz wrapper that maps
  the error channel to an out-parameter or status code, which the TypeScript
  binding re-raises as a typed error. See
  [docs/01-bridge.md](docs/01-bridge.md).

### 5.2 Agent self-correction pipeline (`@xz-lang/agent`)

- **P0** — Automated loop: LLM prompt → code gen → `xz check-json` → context
  injection → auto-repair.
- **P0** — Strict N-step retry threshold (default `N = 3`). Escalate to human
  review when unresolved.
- **P0** — Parse and rank diagnostics by `severity`, `code`, `category`, and
  `suggestion.confidence`; inject only the relevant slice into the next prompt.
- **P1** — Diagnostic filtering by AST line range to optimize token
  consumption.
- **P1** — Refuse to let the agent edit raw TypeScript routing or infra files
  without an explicit developer flag (safety-first, see §8).

### 5.3 Human audit interface (`@xz-lang/audit`)

- **P0** — Next.js dev-server overlay/route (`/___audit`) listing generated
  modules awaiting approval.
- **P0** — Visual badges for function side effects, derived from Xz's effect
  vocabulary:

  | Xz `@effects` | Badge | Meaning |
  |---|---|---|
  | `none` | `PURE` | No side effects; memory local. |
  | `mut` | `MUTATES_STATE` | Explicit internal `mut` modification. |
  | `io` | `IO` / `NETWORK_OUT` | Filesystem, clock, or network I/O. |
  | `chan` | `CONCURRENCY` | Channel `send`/`recv`. |
  | `extern` | `EXTERNAL_FFI` | Raw C ABI / foreign call. |

- **P0** — Show declared vs. derived effects and any `@trusted` stamps, so an
  unproven claim is visible at approval time.
- **P1** — One-click approval that triggers `xz build --shared` and a git
  commit workflow.
- **P1** — `xz check --strict` parity: block approval of modules with unproven,
  untrusted claims.

## 6. Key performance indicators

| Metric | Target | Description |
|---|---|---|
| AI self-correction rate | ≥ 85% | Compiler errors resolved by the agent via `xz check-json` with no human intervention. |
| Human audit time | < 10 s / module | Average time to review and approve an AI-generated Xz module using badges. |
| FFI execution latency | < 0.5 ms | Overhead of calling a compiled Xz function from a Next.js Server Action, excluding the function body. |
| First-pass compilation rate | ≥ 60% | Initial AI-generated `.xz` files that pass `xz check-json` on the first attempt. |
| Unhandled runtime crashes | 0 in production | Approved Xz modules raise no unhandled runtime exception, guaranteed by `Result` types and strict static contracts. |

Targets are measured per release on the benchmark suite introduced in
[docs/05-roadmap.md](docs/05-roadmap.md) Phase 1.

## 8. Non-functional requirements

1. **Safety first.** The AI Agent is restricted from editing raw TypeScript
   routing or infrastructure files without explicit developer flags.
2. **Deterministic reproducibility.** Given the same LLM prompt and Xz version,
   compilation output must produce identical binary behavior.
3. **Developer ergonomics.** Installing `next.xz` requires zero changes to
   existing standard Next.js App Router conventions.
4. **No silent degradation.** A value that cannot cross the C ABI safely is a
   hard error, never a lossy cast.
5. **Version pinning.** The bridge records the Xz compiler version it was
   built against and refuses to bind an incompatible `.so`.
6. **Observability.** Every FFI call can emit a structured record (function,
   declared effects, latency, outcome) for production auditing.

Details: [docs/04-nfr.md](docs/04-nfr.md).
