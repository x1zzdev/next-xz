이 저장소(`next.xz`)에서 이어서 작업한다.

## 규칙 문서 (먼저 읽는다)
`AGENT.md` → `prd.md` → `ARCHITECTURE.md` → `docs/01..05` → `README.md` → `NEXT.md`.
Xz 언어 자체의 동작이 궁금하면 Xz 레포(`~/Xz`, https://github.com/x1zzdev/Xz)의
`docs/`를 확인한다. 여기서 Xz 스펙을 중복 정의하지 않는다.

## 이번 작업 결정
- `$ARGUMENTS`가 있으면 그것을 이번 작업으로 삼는다.
- 없으면 `NEXT.md`의 미완료 최상단 항목.

## 초기 단계 개발 규칙 (Xz와 다름)
이 저장소는 아직 초기 단계다. Xz의 "최소 기능 단위" 규칙 대신 다음을 따른다.
- 기본 구조(모노레포, 패키지 경계, 로더/제너레이터 골격)가 잡힐 때까지는
  **수직 슬라이스 단위로 과감하게 개발**한다. 여러 파일을 만들어도 좋다.
- 단, **최소 기능이 실제로 동작할 때마다 즉시 커밋**한다. 한 커밋은 하나의
  동작하는 증분이어야 하며, "다 만들고 한 번에 커밋"하지 않는다.
- 커밋 메시지는 결정을 말한다: `Load Bun FFI symbols with version check`,
  not `Update bridge`.

## 구현
- 추론이 필요한 핵심 로직(로더, 제너레이터, 재시도 루프, 카드 모델)은 직접 작성한다.
- 보일러플레이트·테스트 골격·문서 등 기계적 작업은 `task` 도구로 `scaffold`
  서브에이전트에 위임해도 된다.

## 검증 (추측 금지, 저장소가 정의한 명령만)
- `.xz` 예제/계약: `xz check-json <file>` (필요 시 `--strict`).
- TS/JS: `package.json`의 스크립트가 생기면 `npm run typecheck`/`lint`/`test`.
  스크립트가 없으면 새로 만들지 말고, 무엇을 검증할지 보고한다.
- FFI 로더: 실제 `.so`가 없으면 stub/모킹으로 단위 테스트하거나, 검증 불가를 보고한다.

## 커밋
`AGENT.md`가 자율 커밋을 요구한다. 슬라이스 내 동작 증분마다 커밋하고,
작업이 끝나면 원격(`origin main`)에 푸시한다.

## 마지막 필수 단계 — 건너뛰지 않는다
`NEXT.md`에서 이번에 완료한 항목을 `[x]`로 바꾸고, 작업 중 발견한 후속 작업을
`## 발견한 후속 (백로그)`에 `- [ ]`로 추가한다. 체크박스 형식(`- [ ]` / `- [x]`)을
그대로 유지한다. `$ARGUMENTS`로 NEXT.md에 없는 작업을 했으면 항목을 새로 추가한
뒤 완료 처리한다.
